# 项目架构与分析报告总览

本文档用于汇总本仓库新增的架构类说明，方便按主题快速查阅。

## 文档导航

| 文档 | 主题 | 适合阅读场景 |
| --- | --- | --- |
| [系统架构报告](./系统架构报告.md) | 系统模块、职责边界、主流程、核心交互 | 想快速理解“项目由哪些部分组成、谁负责什么” |
| [数据流与分层报告](./数据流与分层报告.md) | 数据来源、ETL 流程、表分层、作业四层映射 | 想搞清“数据从哪里来、怎么处理、落到哪里去” |
| [产品说明与业务场景](./产品说明与业务场景.md) | 产品能力、页面功能、业务价值、使用场景 | 想从产品/课程作业角度理解这个系统做什么 |
| [技术栈与部署架构](./技术栈与部署架构.md) | 技术栈、容器拓扑、开发/运行模式、关键依赖 | 想从工程实现角度理解系统怎么搭起来 |
| [项目评审报告](./项目评审报告.md) | 现状、问题、优化方案、挑战与未来工作 | 想用于课程评审、答辩陈述或迭代规划 |
| [项目改进计划说明书](./项目改进计划说明书.md) | 分阶段目标、工程顺序、排期、里程碑和验收标准 | 想把优化方案转成可执行计划 |

## 建议阅读顺序

1. 先看 [系统架构报告](./系统架构报告.md)，建立整体视图。
2. 再看 [数据流与分层报告](./数据流与分层报告.md)，理解离线数据链路。
3. 然后看 [产品说明与业务场景](./产品说明与业务场景.md)，把技术实现和业务目标对应起来。
4. 最后看 [技术栈与部署架构](./技术栈与部署架构.md)，理解工程落地方式。
5. 如果要做课程评审或规划后续优化，再看 [项目评审报告](./项目评审报告.md)。
6. 如果要进入具体实施，再看 [项目改进计划说明书](./项目改进计划说明书.md)。
